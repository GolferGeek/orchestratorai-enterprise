# Using Incident Postmortem

## Start

1. In **Engineering**, open **Workflows → Reliability → Incident Postmortem**
   and choose **New**.
2. Give the incident a **title** and paste its **timeline and notes**: times,
   what was seen, what was done, what fixed it, who was affected and how many.
   More detail gives a better draft; the writer never invents what is missing.
3. Choose **Write the postmortem**. It takes about a minute.

## Approve the action items

The run stops on **Review** with the proposed action items (title, owner,
priority, due, and why).

- **Approve all** keeps them as proposed.
- Per item: **Accept**, **Drop**, or **Rewrite** the action's wording, then
  **Submit item decisions**.

Each approved item is then created as a task in the team's tracker.

## Read it

- **Result**: severity, summary, impact, timeline, root cause, factors,
  lessons, and the action items with their task ids.
- **Trace**: Jev's severity answers and each agent's input and output.
- **Download** the postmortem as PDF, Word or Markdown.
